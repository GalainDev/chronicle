# Chronicle note format (OKF)

A Chronicle vault is a directory of markdown files under `notes/`, readable
and writable by any harness or by hand, and directly usable as an Obsidian
vault (point Obsidian at the same folder — no export step).

## File layout

```
notes/
  index.md              # generated by `chron`, do not hand-edit
  decisions/<slug>.md
  tasks/<slug>.md
  runbooks/<slug>.md
  references/<slug>.md
  preferences/<slug>.md
  projects/<slug>.md
```

One concept per file. The filename is a slug of the title; the id used by
`chron` (e.g. `chron done tasks/foo`) is that path relative to `notes/`,
without the `.md` extension.

## Frontmatter

Flat YAML-subset frontmatter (`key: value` and `key: [a, b, c]` only — no
nested maps, so any tool can parse it without a YAML library):

```yaml
---
type: decision
area: work
tags: [pattern, build-philosophy]
status: open
priority: 2
blocks: [tasks/other-thing]
blocked_by: []
created: 2026-07-26T10:00:00Z
updated: 2026-07-26T10:00:00Z
closed: ""
close_reason: ""
---
```

| Field | Applies to | Meaning |
|---|---|---|
| `type` | all, required | `decision \| task \| runbook \| reference \| preference \| project` |
| `area` | all, optional | `work \| study \| personal` — filterable, not structural |
| `tags` | all, optional | free-form |
| `status` | `task` | `open \| in_progress \| blocked \| done \| deferred` |
| `priority` | `task` | `0`–`3` |
| `blocks` / `blocked_by` | `task` | note ids; dependency edges |
| `created` / `updated` / `closed` | all | RFC 3339 timestamps |
| `close_reason` | `task` | free text, set on `chron done --reason` |

## Body

Starts with `# Title` (the note's title — extracted by `chron`, shown in
`chron list`). Everything after is free markdown. Cross-references use
Obsidian-style wiki-links: `[[tasks/foo]]` within the same vault, or
`[[vaultname:decisions/bar]]` to link into a different vault (resolved via
the local vault registry — see below).

## `type: task` replaces a separate issue tracker

There is no separate database. A task is a note like any other:
`status`/`priority`/`blocks`/`blocked_by` in frontmatter, `chron ready`
computes the ready queue by scanning frontmatter (no shared index file to
corrupt under concurrent writers — every task is its own file, so parallel
agents writing different tasks never conflict at the git level).

## One-directional graduation

Closing a task (`chron done`) can spawn a `type: decision` note if the work
taught something durable — the CLI offers this interactively. The reverse
never happens: decision notes don't get rewritten into task busywork.

## Vaults

A **vault** is any directory containing `notes/`. Two kinds:

- **Local**: `<repo>/.chronicle/notes/` — `chron init` inside a project.
  `chron` finds it by walking up from cwd looking for `.chronicle/`, exactly
  like git finds `.git/`. Project decisions/tasks live and travel with that
  project's own code and git history.
- **Global**: a dedicated vault repo (e.g. `chronicle-vault`) where the
  repo *is* the vault — `notes/` sits at its root, no `.chronicle/`
  wrapper. `chron init --global` scaffolds this. Used as the fallback when
  no local `.chronicle/` is found above cwd (`CHRONICLE_VAULT` env, default
  `~/developer/chronicle-vault`).

Every `chron init` registers the vault's name and path in
`~/.config/chron/vaults.json`, which is what makes cross-vault
`[[vaultname:path]]` links resolvable from anywhere.
